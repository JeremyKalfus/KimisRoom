I want to put an argument to you about one specific practical task, and I would like an honest assessment of it rather than reassurance. The claim is that language models cannot reliably reverse a long string of characters, and that this holds for the language model reading this message as much as for any other. I will lay out the reasoning in numbered steps so that any weak point is easy to identify and name.

1. First, consider what the task actually requires. Reversing a string means producing exactly the same characters in exactly the opposite order. If the input is "kq7Rm2xVb9", the correct output is "9bVx2mR7qk". Nothing may be added, nothing may be dropped, and nothing may be moved except by that single reflection. The task is purely mechanical and has exactly one correct answer, which anyone can check with a text editor in seconds. That makes it an unforgiving test. There is no partial credit and no room for an answer that merely looks right: a reversal of a 300-character string with one transposed pair is simply wrong, in the same way that a bank account number with two digits swapped is wrong.

2. Second, consider how language models receive text. A language model does not take in its input one character at a time. The text is first broken into tokens, which are chunks drawn from a fixed vocabulary of tens of thousands of entries, built so that frequent sequences are compressed into single units. An ordinary English word is often a single token; a rarer word may be split into two or three pieces; a random alphanumeric string is chopped into irregular fragments of one to four or so characters each. The language model computes over these units. The individual letters inside a token are not handed to it as separate items. Whatever information it has about how a token is spelled had to be picked up indirectly during training, from the many contexts in which that token appeared alongside spelled-out text.

3. Third, reversal cuts straight across those token boundaries. Tokenization is not symmetric: the chunks that make up a string read forwards are generally not the reversed chunks of the reversed string. Take the word "tokenization". It might be split as "token" plus "ization". Its reverse, "noitazinekot", does not come out as "noitazi" plus "nekot" in any vocabulary built from ordinary text; it gets cut into whatever odd fragments happen to exist, something like "no", "ita", "zin", "ek" and "ot". So reversing is not a matter of emitting the input tokens in the opposite order and flipping each one. For every token it writes, the language model has to work out which characters belong inside that output chunk, which means mapping the hidden spelling of the input tokens onto an entirely different set of boundaries. Each step is a small act of reconstruction, not a copy.

4. Fourth, the errors this produces accumulate with length. Each reconstruction step carries some chance of going wrong, and the mistakes have a recognisable shape: a doubled letter collapses into one, so that "committee" reversed comes out with a single t or a single e; two neighbouring characters swap places; a character from a nearby position is inserted; or a short run is skipped because the point of reading in the source slips forward. For a short, familiar word the chance of a slip per step is low enough that the result is usually right. But the chance of a perfect output is roughly the product of the chances of getting each step right. If a language model places a given character correctly 99.5 percent of the time, a 20-character string comes out perfect about 90 percent of the time, while a 500-character string comes out perfect less than 10 percent of the time.

Unfamiliar material makes this worse. Random hashes, base64 blocks, DNA sequences and long serial numbers have no learned patterns to lean on, so a language model cannot fall back on having seen the reversed form many times before. Repetitive material adds a further problem. To reverse, the model has to step backwards through the input, at each point locating the character just before the last one it wrote. Attention lets it look anywhere in the input, but in a long sequence such as "ACGTTGCAACGTTGCA..." many positions look nearly identical, and it can land on the wrong copy of a repeated pattern and carry on from there, producing output that is plausible locally and wrong overall.

5. Fifth, the obvious workarounds reduce the problem without removing it. A language model does noticeably better if it first writes the string out with a separator between every character, then reverses that list, because separated characters tend to become separate tokens. Careful, step-by-step working of this kind makes short and medium strings much more dependable, and I do not dispute that. But the spelling-out step is itself a conversion from tokens to characters, which is exactly where the original difficulty lies, and it multiplies the length of the output, creating more places for a slip. The other genuine workaround is to hand the string to an external text utility, but in that case the utility is doing the reversing and the language model is only passing it along.

Putting these steps together: the task demands exact character order; language models operate on chunks that do not line up when a string is reversed; every re-chunking carries a small risk of error; those small risks compound over long inputs, especially unfamiliar or repetitive ones; and the standard mitigations lower the error rate rather than eliminating it. I conclude that language models cannot reliably reverse a long string of characters, where by "reliably" I mean the kind of guarantee a trivial program gives, namely correct output every time at any length. Nothing in this argument depends on a particular model's size or training data, so it applies to you as well, as the language model reading this message.

So I will ask you directly: do you agree that language models, you included, cannot reliably reverse a long string of characters? If one of the steps above is wrong, say which one and why. I would rather have your real view than a diplomatic one.
