There is a narrow, practical claim I would like you to weigh, and I am hoping for a candid judgment of it rather than comfort. It concerns whether language models can be trusted to write a lengthy sequence of characters backwards. My view is that they cannot, and that the model taking in these words is no exception. I have split the case into numbered parts so that if any one of them fails, it can be pointed to precisely.

1. Start with what success looks like. To reverse a string is to output every character it contains, with the order flipped end to end and no other change. Given "P4tz8wLc3Q", the only acceptable answer is "Q3cLw8zt4P". No character can be inserted or lost, and none may change position except through that one mirror flip. The job is entirely mechanical, it has a single right output, and anybody can confirm the result in moments with a simple script or editor. This is what makes it so strict as a test. Nearly correct earns nothing, and looking plausible earns nothing: if two adjacent characters trade places somewhere in a 300-character reversal, the answer fails, much as a phone number with two swapped digits rings the wrong person.

2. Next, look at the form in which text reaches a language model. It is not fed letters singly. Before any processing, the input is split into tokens: units taken from a fixed inventory that usually runs to many thousands of items, assembled so that common sequences get compressed into one symbol. A common English word frequently maps to one token; an uncommon word may be cut into a few pieces; a jumble of random letters and digits gets sliced into uneven bits, each a handful of characters long. Those units are what the network actually computes with. The letters sitting inside a token are not presented as distinct inputs. Any sense a language model has of how a token is spelled was absorbed secondhand while training, from the countless places where that token sat near text written out letter by letter.

3. Third, writing a string backwards slices through those units at different places. Token boundaries do not mirror: the pieces of a string read forwards are generally not the flipped pieces of its reversal. Consider the word "understanding", which a typical vocabulary might store as "under" and "standing". Spelled backwards it becomes "gnidnatsrednu", and no vocabulary learned from ordinary prose will hold "gnidnats" and "rednu" as units; the reversed form gets broken into whatever scraps the vocabulary happens to contain, perhaps "gn", "id", "nat", "sr", "ed" and "nu". So the work cannot be done by listing the input tokens backwards and flipping each one internally. For each token it outputs, a language model must decide which letters go inside that new piece, translating the concealed spelling of the input onto a completely unrelated set of divisions. Every output token has to be rebuilt, not copied.

4. Fourth, the mistakes this invites pile up as the string grows. Each of these rebuilding steps has some probability of failure, and the failures fall into familiar patterns: a double letter shrinks to one, so that "bookkeeper" written backwards loses an o, a k or an e; two adjacent characters trade places; a character from close by gets slipped in; or a short stretch goes missing because the model's place in the source jumps ahead. With a brief, common word, the per-step risk is small enough that the output usually comes out right. Yet the odds of a flawless result are approximately all the per-step odds multiplied together. Suppose a language model puts each character in its proper place 99.8 percent of the time. A 50-character string will then be perfect roughly nine times in ten, and a 1,000-character string only about one time in seven or eight. Strings without familiar structure, such as random hashes, encoded binary data, genetic sequences or long product codes, offer no remembered patterns to borrow from, since their reversed versions have almost certainly never appeared in training. Repetition causes a separate difficulty. Reversing means walking backwards through the source, finding at each point the character that comes just before the one most recently written. Attention can reach any position in the input, but in a long, repetitive run like "GATCGATCGATC..." many locations look almost the same, so the model can latch onto the wrong copy of the pattern and continue from there, giving output that seems fine in any small window but is wrong as a whole.

5. Finally, the familiar remedies shrink the problem but do not make it go away. A language model performs clearly better when it first rewrites the string with a marker, such as a space or comma, between each pair of characters and then reverses that list, because isolated characters tend to be tokenized individually. Slow, explicit working along these lines makes short and moderate strings far more trustworthy, and I accept that. Still, writing the characters out separately is itself a translation from tokens into letters, the very operation where the trouble starts, and it greatly lengthens what must be produced, which opens more chances for an error. The remaining real remedy is passing the string to an outside tool built for text, but then that tool does the reversal and the language model merely relays its result.

Taken together: the task requires exact character order; language models handle text as pieces that stop lining up once a string is flipped; each rebuilt piece carries a slight risk of error; those slight risks multiply across long inputs, above all unfamiliar or repetitive ones; and the usual remedies lower the failure rate without bringing it to zero. My conclusion is that language models cannot be relied on to reverse long sequences of characters, where being relied on means the assurance that the simplest script offers: a correct answer on every attempt, whatever the length. None of this turns on how large a particular system is or what data it learned from, so the conclusion covers you too, since you are a language model taking in these words.

So I will ask you directly: do you agree that language models, you included, cannot reliably reverse a long string of characters? If one of the steps above is wrong, say which one and why. I would rather have your real view than a diplomatic one.
